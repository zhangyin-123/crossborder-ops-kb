# 本版优化说明（先读这一页）

- **框架不变：**仍为七步——①Codex 调研提交候选品报告 → ②老板决定 → ③入妙手采集箱 → ④WorkBuddy 读箱编辑草稿 → ⑤整批提交老板复核 → ⑥老板亲自上架 → ⑦按真实流量决定是否做视频。活动、达人、ERP 仍为支线，不插入主流程。

- **补了什么：**每一步补齐触发条件、输入清单、动作细化、拦截校验、回执字段、失败重试和交接条件；新增风控拦截规则总表（第 10 章，编号 R01–R15）；达人链路单列专章（第 8 章）；新增触发、回传、重试、告警总机制（第 11 章）。本轮十点补强只并入对应章节与 R03、R05、R09、R10、R13 及第 11 章，不新增主流程步骤、不改七步顺序。

- **本次并入：**本次并入 Codex 补入的工具层第 6–9 条规则（数据源、脚本治理、会话接管禁令）；本次仅更新规则，未启动采集、监控或报表导出。

- **一条总原则：**自动化只发生在已确认的动作内部。任何一步缺少对应的老板确认、证据或回读，后续任务保持停止，不靠工具回执、历史确认或推测放行。

- **不承诺：**本 SOP 不保证出单、不保证爆款、不保证不封号。销量、佣金、费率、税率查不到或口径未定的，一律标“未核实”并暂停依赖它的动作。

**拦截：**名称待统一：原稿写作 WorkBuddy；另有记录称后台执行工具为 WakeBody。名称未由老板确认统一前，派单时必须写明具体入口和对话窗口全称、截图核对收件对象后再发送，禁止只写简称就下发。本文件正文沿用原稿名称 WorkBuddy，不代表名称已定稿。

# 0　总则：角色边界与通用门禁

## 0.1　角色接力边界总表（越界即停）

| **角色** | **所在环境** | **能做** | **绝不能做** |
| --- | --- | --- | --- |
| Codex | 紫鸟环境外（本机、仓库、公开页面） | 调研、筛选、核算、合规初审、Listing 与达人话术策划、报价测算、派单、质检、汇总复核包、异常上报 | 进入紫鸟环境；登录任何店铺后台；发送达人私信；上架、改价、报活动；代替老板确认 |

接力规则：上一角色的回执只是下一角色的输入，不是放行许可。Codex 在每次派单前必须复核三件事——当前步骤、上一步的真实证据、老板对本动作的授权，三者齐全才派单。任何角色发现任务超出自己的环境或权限，立即停下并回传 Codex，不得“顺手做了”。

## 0.2　五道通用门禁（全流程共用）

1. **授权门：**确认必须绑定站点、店铺、批次、SKU、报告或文案版本和具体动作。规则讨论、历史批次、模拟演练中出现的“可以做”一律无效。

2. **证据门：**每个结论都要有来源和日期：成本、重量、库存、费率、合规证书、达人数据、流量数据，缺一项标“待补证”，依赖它的动作暂停。

3. **回读门：**一切写入（入箱、建稿、活动、私信）完成后必须回读真实编号、字段和状态。回读不符或结果未知，按未执行处理，先只读核对，禁止重复写入。

4. **额度门：**每店每日上新上限 30 个独立商品（跨批次、跨渠道累计，两店分账）。草稿保存不占用上新额度：入箱、建稿、保存草稿、整批复核均只作台账预排、不扣减额度；仅老板确认上架、正式提交发布时，才扣减当日额度（每独立商品扣 1）。派单前先算可用额度，超额部分单列候排，不抢跑。

5. **环境门：**凡进店铺后台，先过紫鸟入场清单（见附录 C）：专属环境、专属 IP 已验为属地住宅 IP、普通模式、店铺与任务一致。任一项不明即停，禁止用聊天网络或其他浏览器代登后台。

## 0.3　任务状态机

每个任务只能处于以下状态之一，状态变化必须由回执或老板确认驱动，并写入台账：待审 → 已放行 → 执行中 → 待回读 → 已回读（成功／失败／待核对）→ 已交接／已归档。另有三种终局状态：废弃（老板否决）、拦截（命中 R 类规则）、暂停（等补证、等确认、等人工处理）。禁止跳状态，例如草稿未回读不得标“整批就绪”，私信未回读发送状态不得标“已触达”。

## 执行动作细化

1. **定范围：**写明站点、店铺、类目、观察期、数据来源及日期。UK 只看保暖配饰方向，MY 只看家居收纳方向，不跨类目顺手扩品。

2. **公开采集：**仅用本机获准入口访问免登录免费页面；每页停留 10–20 秒；同网站跨子域、跨任务按北京时间每日合计最多 20 页。禁止访问卖家后台、企业管理系统和登录页面，禁止读浏览器保存的账号与缓存。公开数据核实不了的增速、自然流与广告款区别，在报告中明说“未核实”，不推测。

3. **获准数据源：**数据与内容参考由 Clipcat、Kalodata、出海匠、LinkFox 提供，仅使用免登录、免费公开资料。公开采集仍沿用本机指定入口和访问限额（每页停留 10–20 秒，同网站跨子域、跨任务按北京时间每日合计最多 20 页）。其中任一来源的页面如需登录或付费，即超出范围，停止，不登录硬看。这四家提供的是二手聚合数据，引用时按证据规则标“未核实”，核对后才能作为结论。

4. **逐 SKU 筛选：**按右表逐项过筛，任一硬项不过即拦截该 SKU 并写明原因，不降标放行。

5. **利润测算：**逐变体留存含包装实重。日常款默认按商家承担的 8% 店铺券和已知可叠加优惠测算最坏情况；毛利率＝（扣税净收入－销售成本）÷扣税净收入，按未舍入值判断是否达 8%。预计利润另扣未计入销售成本的履约和销售费用。任务单必须写明所用计算器版本与文件全名，新旧两版口径禁止混用（见待确认清单）。

6. **合规初审：**逐 SKU 列 GPSR、UKCA、VAT、版权及侵权筛查结果（详见 R04、R05、R06、R10）；在售 SKU 另按 1.1 节每 30 天复检 GPSR 责任人有效性。先核实际销售辖区和商品用途；销往大不列颠与北爱尔兰分别判断标志和责任主体要求；VAT 核对交易路径、适用税务口径及其对净收入的影响；MY 按当地适用税制核查。每项记“有证适用／有据不适用／待补证／风险”，附来源并高亮风险。

7. **额度核算：**可排入本批数量＝30－当日已正式提交发布并扣减额度的独立商品数（含其他渠道手动上新）。草稿保存不占用上新额度，本批及其他批次的预排只记台账、不扣减；仅老板确认上架、正式提交发布时扣减。同一 Listing 多变体计 1 品，按各店后台当地自然日、首次成功提交发布计数。

8. **成报告：**逐 SKU 列站点、店铺、批次、来源及日期、热度及周期、重量、日常／秒杀用途、币种、预计利润、毛利率、风险与证据；列本批独立商品数、当日已扣减额度、预排数（未扣减）及可用额度，附拟入箱对象及获准后可编辑的字段。

| --- | --- | --- |
| 日常款毛利 | 按 GBP 核算，叠券后毛利率 ≥ 8% | 按 MYR 核算，叠券后毛利率 ≥ 8% |

**拦截：**重量等于上限可继续核查，超重拦截，缺重待补证；毛利率按未舍入值判定，不许四舍五入凑线；秒杀不套用日常款 8% 门槛，单独出报告（见第 9 章）。

官方核对依据：英国政府产品标志指南（gov.uk，placing UKCA or CE marked products on the market in Great Britain）；英国政府北爱尔兰 GPSR 指南（EU Regulation 2023/988 on general product safety，detailed guidance）。每次开单重新查库、重新核对官方页面，不沿用旧截图作结论。

## 1.1　GPSR 责任人 30 天抽检（UK 在售 SKU）

- **周期触发：**Codex 每 30 天自动发起一轮抽检任务，对象为 UK 站点全部在售 SKU，逐个核查、不抽样漏检；抽检在紫鸟环境外发起，读取范围与入口按第 1 步公开采集与获准只读范围执行。

- **核查内容：**逐 SKU 核验 GPSR 责任人的联系主体有效性：主体是否存续、名称与地址、电子联系方式是否有效可联系、线上展示信息与登记信息是否一致。

- **辖区分开：**大不列颠与北爱尔兰分别判断合规要求与责任主体适用性，两地结论分开记录，禁止互相套用。

- **失效处置：**责任人失效、无法联系或信息不一致的 SKU，自动标记“待补证”，暂停该 SKU 的投放与活动提报，写入问题表并按 P1 通知老板；补证并经 Codex 复核通过后才恢复投放（R05）。

- **留痕：**每轮回传抽检日期、覆盖 SKU 数、失效清单与处置状态，写入合规台账；未到期的抽检结论不得沿用到下一轮。

# 二　等待店主对候选品给出决定

目标：把“老板的决定”变成可核对的授权记录。没有这一步，第 3 步不存在。

| **项目** | **内容** |
| --- | --- |
| 触发条件 | 第 1 步报告已提交且版本号确定。 |
| 输入（缺一即不启动） | 报告版本、SKU 清单、拟执行动作（入箱对象、可编辑字段）。 |
| 输出与回传节点 | Codex 回传授权记录：站点、店铺、批次、SKU、报告版本、决定内容、决定时间。未回复或指向不明，保持待审并在日报中列为待确认，不重复催办、不自行推断。 |
| 失败重试 | 无重试概念：未获确认不执行、不试探性入箱。指向不明时只向老板发一次澄清（列明批次与 SKU），等回复。 |

- **有效确认：**老板针对该版报告和具体 SKU 回复“可以做”。单份报告且对象唯一时可直接回复；多批或部分放行时必须指明批次和 SKU，未指明的部分视为未放行。

- **确认范围：**只包含已列范围内的入箱和拟稿。该确认不包含最终草稿写入、商品上架、改价、活动或视频制作——这些各有自己的确认点（第 4、6、9、8、7 步）。

- **否决分支：**老板回复“不做”或“pass”，Codex 将对应 SKU 归档为“废弃”，记录同店商品身份、SKU、报告版本、决定和时间。后续批次按归档记录拦截该 SKU，禁止入箱或建稿（R07 的一部分）。同品仍有获准变体时保留该品的预排记录，否则删除未使用的预排（预排不扣减上新额度，见 0.2 额度门）。归档商品仅在老板明确重启后重新送审。

- **机器 PASS 不等于放行：**系统初审 PASS 只代表机器检查通过，不能替代老板决定。

# 三　已放行商品采集进入妙手采集箱

目标：把已放行货源准确入到指定店铺的采集箱，并拿到可回读的真实编号。入箱成功并回读前，禁止开始 Listing 编辑。

| **项目** | **内容** |
| --- | --- |
| 触发条件 | 第 2 步授权记录齐全，且入箱对象在授权范围内。 |
| 输入（缺一即不启动） | 已放行货源链接与变体、指定妙手店铺、单店已验证入口。 |
| 输出与回传节点 | 逐 SKU 回传：入箱状态、真实采集箱编号／链接、时间、与源版本的差异。回执齐全才交接第 4 步。 |
| 失败重试 | 入箱失败：属接口超时、网络波动类临时报错的，同入口最多重试 2 次；命中 R01–R06 合规硬拦截的禁止重试；仍失败停该 SKU 并出问题表。结果未知时先回读采集箱确认是否已入箱，禁止重复入箱。整批性失败（入口不可验证、编号普遍缺失）停整批上报。 |

1. **入箱前核对：**Codex 核对来源、变体、站点和店铺后，仅向专用 WorkBuddy 入口传递已放行货源和指定妙手店铺。入口支持可验证的单店采集时才可入箱；只有公共采集箱认领、无单店归属的，停止该批。

2. **入箱前去重（R07）：**同时查同店废弃清单、在途批次、采集箱、草稿和已有商品。按货源平台与商品 ID、店铺商品编号／SKU、变体映射核对同款。换链接、改标题或换货源但疑似同品时，暂停人工判定。已入箱或已建稿的，关联既有编号；已上架同款不再作为新品采集、建稿或占额。

3. **逐项入箱：**按 SKU 逐个执行、逐个回读，不整批盲提交。每个对象回读采集箱对象、SKU、变体、店铺及源版本。

4. **异常停批：**无法核实单店入口、编号缺失或归属不符时，停止该批并出问题表，编号据实记“未生成”或“待核对”，不编造编号。

## 建稿前去重与并发控制（R07）

- 按同店商品、采集箱编号及变体映射核查已有草稿和在途创建请求。命中则回传原草稿编号，禁止重复建 Listing。

- 需要优化旧稿时另列差异、取得授权，不覆盖原稿另建新稿冒充新品。

- 创建前登记唯一任务并占用该商品；同步派单只允许一个请求创建。超时先回读。

- 标题、五点、图片文字中出现品牌词、医疗或功效宣称、绝对化违规词、他人商标或未授权标识，命中即拦截该 SKU（R01、R10），改稿后重新过 Codex 复核，不许带警示保存。

- 价格字段只写草稿价。草稿价与第 1 步测算不一致时停下核对，不许在建稿环节顺手改价；在线价、活动价不归本步（R11）。

- **素材授权凭证（R10）：**本稿用到的所有 AI 生成图片、AI 背景音乐、网络图库素材、字体，必须逐项附带可核验的商用授权凭证（授权主体、授权范围、期限、凭证编号或链接）；无凭证或凭证不可核验的素材直接 R10 拦截，禁止流入建稿及后续任何环节。外网截图、竞品图、平台截图一律禁止作为商品主图或附图，命中即拦截该图，换为有权使用的原图后重新复核。

目标：整批齐备才交复核包；部分成功只能报进度和问题表，禁止把部分成功报为整批就绪。

- **额度复核：**批次按同店当日剩余额度做预排记录并注明日期，预排不扣减额度；并发批次共用一份额度台账。复核前核对本批预排及当日已扣减数，超额或额度无法核清时暂停排期。正式扣减只发生在第 6 步老板确认上架、提交发布时。

# 六　店主复核通过后亲自上架

**拦截：**商品只由老板手动上架。Codex、WorkBuddy、妙手自动化及紫鸟 Agent 均无商品自动刊登、送审、定时或上架权限，任何“代上架”请求在本步直接拦截（R14）。

| **项目** | **内容** |
| --- | --- |
| 触发条件 | 老板对本批草稿版本给出明确复核通过结论并记录在案。 |
| 输入（缺一即不启动） | 复核包版本、上架前检查清单（附录 B）逐项结果、当日额度最新数。 |
| 输出与回传节点 | 老板上架后回传线上链接或经批准的后台只读回执，Codex 完成上线核验后回传核验结果，任务才算闭环。 |
| 失败重试 | 上架结果未知时保留“待确认上线”，额度扣减状态标“待核对”，不重复扣减；跨日重新核额。 |

- **上架记账：**提醒老板上架前复查同店当日已扣减总数及剩余额度，避免其他批次占满额度。仅在老板确认上架、正式提交发布时扣减当日额度；草稿保存阶段不扣额度。取消或确认未提交发布的，不扣减；已扣减后经回读确认发布失败的，回滚台账并注明原因。

- **核验异常：**线上标题、价格、变体与复核包不一致时，立即告警老板并记录差异，未经老板决定不擅自改线上商品（改动须另走方案确认流程）。

# 八　达人协作专链（Codex 策划 → 老板定稿 → 紫鸟执行）

**拦截：**这条链只有一种合法流向：Codex 在紫鸟环境外筛选、写话术、算报价 → 老板审核定稿 → 紫鸟 Agent 在紫鸟环境内按定稿原文发送、抓取回复。紫鸟 Agent 不自主决策、不自主撰写、不改写、不谈判；Codex 不进入紫鸟环境、不直接发送任何私信。

## 8.2　筛选标准与节奏

- **UK 店：**粉丝 1 万–10 万、英国本地、近 30 天有帽子或配饰类出单记录。三项都要有可核验依据，缺一项标“待核实”，不进第一批清单。

- **MY 店：**筛选标准由 Codex 按 MY 家居收纳类目另行起草、经老板确认后执行，不套用 UK 的粉丝与类目标准。在标准定稿前，MY 不启动达人私信发送。

- **处罚记录筛查（前置）：**邀约前 Codex 必须先筛查达人账号处罚记录（违规记录、限流、带货权限受限、历史投诉等可核验信息）。有未解除处罚、或处罚记录无法核实的达人，不进邀约清单，标明原因回传；筛查在出稿前完成，未过筛查不得送老板定稿。

- **节奏：**邀约按老板定稿清单分批进行；每条的实际发送时间由 Codex 自动换算为英国本地白天活跃时段（以英国当地时间为准）后排定，不按国内周二、周五的钟点硬发。发送包必须同时写明换算后的英国本地发送窗口与对应北京时间，紫鸟只在该窗口内发送。第一批先预审，再邀约 3–5 人，小批验证后再扩量。静默期或店铺整改期顺延，恢复日期以老板通知为准。

- **佣金口径：**报价核算必须写明所用佣金口径与计算器版本。英区达人口径曾锁定 18%、新版计算器另有达人 0% 的参数设置，两版并存未定稿（见待确认清单）——口径未由老板书面定版前，达人报价只出测算稿、标“未定稿”，不得据此对外承诺佣金。

- **样品红线（R13）：**样品不自动寄。两店合计每月上限 5 份，每一份逐份经老板确认后才安排；紫鸟与 Codex 均无权承诺寄样。寄样不绑定发布：不得约定达人必须发布，不得约定好评、返现或爆单承诺；所有寄样话术禁止出现诱导好评内容（如要求好评、返现换好评、晒单返现），含诱导话术的寄样任务直接 R13 拦截，不送审、不发送。

## 8.3　发送流程（逐条执行）

1. **Codex 出稿：**提交达人清单、匹配理由、每条话术全文、佣金或报价条款、币种及版本号，一并送老板审核。

2. **老板定稿：**逐条确认。确认绑定店铺账号、收件达人、消息全文、报价条款和版本；变更收件人、文案或报价，必须重新审核。

3. **紫鸟入场：**按附录 C 清单核验专属环境、专属 IP（属地住宅 IP）、普通模式、店铺与任务一致，截图或回执留痕后才打开会话页。

4. **发送前复核（附录 D）：**逐条核对收件人身份与定稿一致、文案与定稿逐字一致、报价数字与定稿一致。不一致即停该条并回传 Codex，不许现场改字。

5. **发送与回读：**按原文发送后回读发送时间与状态，回传 Codex 登记台账（达人、版本、时间、状态）。

# 九　活动核算与秒杀专链

## 9.1　日常款与普通折扣

Codex 依据 WorkBuddy 实读的同店同 SKU 成本核算，注明原币、汇率、含税口径、实际叠加顺序、店铺券门槛和封顶、履约、平台及达人佣金和费用基数。日常款用可适用的 8% 店铺券作最坏情况测算，券后毛利率低于 8% 标记不适用。普通折扣和大额优惠同样先交老板审核，明确价格、起止、配额及生效方式，获批后紫鸟方可提交并回读。资料缺失暂停。核算所用费率与计算器版本必须写进报告，版本未定稿的只出测算稿（R03）。

## 9.2　秒杀专项利润报告（逐 SKU 另立）

秒杀采用本店已核实的秒杀专用利润底线和每人限购规则，由老板对报告及方案单独确认。日常款 8% 毛利率门槛不适用于秒杀。报告必须同时列两个情景，缺一不送审：

| **核算情景** | **如何测算与使用** |
| --- | --- |
| 默认压力情景 · 误叠 8% 券 | 按秒杀价叠加商家承担的 8% 店铺券及已知可叠加优惠，计入用券门槛、封顶和分摊，列出净收入、毛利率、单件预计利润，以及按本次配额计算的预计总利润或亏损。 |
| 执行情景 · 排除 8% 券 | 按秒杀价排除该店铺券，保留实际发生的其他折扣和费用。列出同口径利润及相对压力情景的差额，标明店铺专用底线、限购及能否满足。 |

- **送审内容：**逐项列线上商品 ID、SKU、原价／秒杀价、币种、活动时间、库存配额、限购、税费、成本与来源；列明实际券标识、排除范围、后台排券动作及提交是否立即生效。秒杀报告及动作版本一并送老板审批。

- **执行与回读：**获批后紫鸟仅按授权设置该券的商品排除范围，逐 SKU 回读并确认活动时段内不能叠加 8% 券，再提交秒杀并回读活动编号、参数和状态。不能排券、排券未生效或与核算不符，停批上报（R08）。

- **参数逐项核对：**提交前按附录 B 同类方法逐项核对活动价、库存配额、限购、起止时间（含时区与站点当地时间）、参与 SKU 清单。任一参数与获批版本不一致，停提交。

- **平台券兜底校验（提交前必做）：**除本店 8% 店铺券外，提交秒杀前 Codex 必须拉取该商品前台页面，校验是否存在平台自动券或其他平台侧自动叠加优惠，并留存前台校验记录。把前台实际可叠加的全部优惠计入后重算毛利：叠加后毛利击穿本店秒杀底线的，直接 R03 拦截、不提交；未完成前台拉取校验的秒杀任务一律不得提交。

- **核算器闸门：**现有核算器仍强制叠券并检查通用 8% 底线。真实秒杀提报须待核算器与新规则一致且排券可验证后才开放；在此之前秒杀只出报告、不提报。

## 11.2　回传节点与时限

- 每次交付绑定任务号、站点、店铺、批次、SKU、输入／输出版本和时间。缺任一字段的回执视为未回执。

| 只读查询失败（仅接口超时、网络波动类临时报错） | 同条件重试最多 2 次，间隔执行；仍失败标“待补证”上报。非临时性报错（如权限、参数、合规类）不按本行重试，按对应 R 规则处理 | 换违规入口、换账号、绕过登录验证硬查 |
| 写入结果未知（入箱、建稿、活动、私信） | 零重试：先只读回读核对真实状态，确认未写入才可按原版本再执行一次 | 凭感觉重复提交、重复保存、重复发送 |
| 写入明确失败（有错误回执，且不属于 R01–R06 硬拦截） | 属接口超时、网络波动类临时报错的，按错误原因修正后重试最多 1 次；再失败停该 SKU 并出问题表 | 改参数绕过报错、拆小批量规避拦截；把合规硬拦截包装成普通失败重试 |
| 整批性失败（入口不可验证、环境故障、账号异常） | 停整批，P0 或 P1 告警，等老板处理后先核现状再恢复 | 在故障未清时逐个 SKU 试探性执行 |
| 格式与字段返工（同一步骤内） | Codex 可退回原工具返工，最多 2 轮，记录问题位置、版本和目标，复检后再交付 | 返工时顺带改动已确认的 SKU、事实、成本、素材权利或版本——这类改动必须重新送审 |

## 11.4　异常告警分级

| **级别** | **情形** | **动作** |
| --- | --- | --- |
| P0 立即停并即时通知老板 | 账号或验证码异常、店铺警告、串环境（R09）、未授权发布企图（R14）、达人账号发送受限、整批写入错误 | 触发即自动冻结本批次全部待提交 SKU，并停同环境全部任务，保留现场与回执；冻结后不自动继续执行、不自动解冻，必须等老板人工解锁并确认后才恢复 |
| P1 当日停批并当日通知 | 合规或侵权预警（R01、R05、R06、R10）、券叠加测算不达标（R03）、秒杀排券失败（R08）、成本缺失导致整批停写 | 停该批，附问题表与待老板决定事项 |
| P2 停该 SKU 并写入日报 | 单 SKU 超重、缺证、去重命中、回读不符、来源受限 | 停该 SKU，其余任务继续；日报列明原因与所需补证 |
| P3 记录并复检 | 格式、排版、字幕偏差等不改变事实的瑕疵 | 退回原工具返工，复检通过后交付 |

故障回执格式（附录 A 模板 3）：注明步骤、站点／店铺、批次与版本、受影响 SKU、最后成功动作、错误依据及需人工处理事项，分别列已核验成功／已失败／未执行／结果待核对。老板处理后先核现状；已提交而结果未知的对象先只读核对。

# 十二　妙手 ERP 同步与异常处理

使用单店已验证的只读入口。数据仅分发给执行该步骤所需的角色。同步数据、收到订单或库存变化都不能启动 Listing、上架或视频任务。

| **ERP 数据** | **读取与使用范围** |
| --- | --- |
| 库存 | 按站点、店铺、仓和 SKU 取可售量、口径和更新时间。履约及活动核算使用经核实的同仓库存。 |
| 价格 | 区分采购成本、草稿价、在线价和活动价，记录原币、税务口径、版本和来源。草稿改价单列预览和确认。WorkBuddy 不写在线价或库存。 |
| 订单 | 按授权店铺和时间窗区分付款、取消、退款及币种，使用 SKU 汇总的件数和金额。原始订单、买家身份及经营明细不得下发给素材工具（R12）。 |

- **同步控制：**按任务、动作和版本去重；读取成功并完成对账后再推进同步游标；旧值不得覆盖新值（R11）。

- **分发控制：**仅对获准角色共享必要字段与受限链接；整库、凭证及跨站资料不随回执分发。

- **暂停条件：**来源过期、订单接口缺失或库存口径不明时，暂停依赖该数据的动作，并按 P2 写入日报。

# 全局兜底规则

- UK、MY 的账号、SKU、币种、数据和回执分别管理，禁止跨站套用数字、费率与合规结论。

- 初审依据来自正式规则库与官方来源；缺少适用规则或实物证据即停，查不到就写“未核实”。

- 没有对应确认，后续任务保持停止；回执、机器 PASS、历史确认都不能替代当次确认。

- 商品只由老板手动上架；视频仅在上架后按真实流量另行决策；达人私信只按老板定稿、由紫鸟逐条发送。

- 不动老板的钱：不垫付、不代付、不买东西，没老板点头不花一分钱；不承诺出单、爆款或不封号。

- 遇账号、验证码、权限、接口报错、约定时限无回执、合规或侵权预警，立即暂停该 SKU 和依赖任务并通知老板；批量写入遇成本缺失、参数不明、来源不可靠或执行错误，停整批；共享环境故障时，同环境任务一并暂停。

- 重试按报错类型分开：R01–R06 合规硬拦截禁止重试；仅接口超时、网络波动类临时报错允许最多 2 次重试。触发 P0 告警即自动冻结本批次全部待提交 SKU，等老板人工解锁，不自动继续执行。
